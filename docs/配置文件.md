# 配置文件

## 数据类型术语

本章介绍数据类型相关术语。

### 时间字面量

忽略空格，由数值、单位两部分组成。如果省略单位，默认为微秒。

单位可以为 `us` `usec` `ms` `msec` `s` `sec` `m` `min` 等。

例：`1500000` 等价于 `1500ms` 等价于 `1500 ms` 等价于 `1.5 sec`。

### 空间字面量

忽略空格，由数值、单位两部分组成。如果省略单位，默认为字节。

单位可以为 `B` `Byte` `K` `KiB` `M` `MiB` `G` `GiB` `T` `TiB` 等。

例：`536870912` 等价于 `524288K` 等价于 `512 MiB` 等价于 `0.5G`。

### Limit

`Limit` 是存放资源限制的结构，包含如下字段：

- `time` 时间限制，默认为 `1s`。
- `time_redundancy` 评测时时间冗余，默认为 `200ms`。
- `memory` 空间限制，默认为 `512 MiB`。
- `memory_redundancy` 评测时空间冗余，默认为 `4 MiB`。
- `stack` 栈空间限制，设置为 `-1` 表示与空间限制相同，这也是默认值。
- `fsize` 输出文件大小限制，默认为 `64 MiB`。

### LangTag

`LangTag` 是描述编程语言标记的字符串，详见 [编程语言-语言标记](./编程语言.md#语言标记)。

## 文件夹结构

本章介绍数据文件夹结构。

本程序不支持符号链接，不建议在数据文件夹中放置符号链接。

> *For Developers* 本程序将迁移到 `pathlib`，替代 `os.path`，期望获得更好的符号链接支持。

### 输入、输出文件和子任务

**输入、输出文件标识** 用于识别输入、输出文件的文件名子串。有别于常见的以文件扩展名（`.in` `.out`）区分输入、输出文件，文件名按照 `.` 字符分割后得到的每个子串都可以作为输入、输出文件标识。包含 `in` 的是输入文件，包含 `ans` 或 `out` 的是输出文件。

> *For Developers* `lib.collect` 提供了强制使用文件扩展名作为输入输出扩展名的方法，详见内部函数 `lib.collect._find_ansfile_strict` `lib.collect_find_ansfile_free`。

**测试点** 由一对输入、输出文件组合而成的测试数据。

**子任务** 一个或多个测试点组成的集合。一般而言，通过子任务中所有测试点才判定为通过该子任务。

数据文件夹根目录下的每个子文件夹和测试点都是一个单独的子任务。子文件夹内部的子文件夹会被递归地加入该子文件夹指代的子任务。

示例：

```
data
├── 1.ans
├── 1.in
├── 2.in
├── 2.out
└── sub
    ├── 3.ans
    ├── 3.in
    └── sub-sub
        ├── 4.ans
        └── 4.in
```

上述文件结构将识别出四个测试点，三个子任务：

1. `1.in, 1.ans`
2. `2.in, 2.out`
3. `sub/3.in, sub/3.ans` `sub/sub-sub/4.in, sub/sub-sub/4.ans`

### 配置文件

有三种配置文件：

1. **manifest.json** 放在数据文件夹根目录，描述评测配置。
2. **config.json** 放在数据文件夹根目录或子文件夹中，描述测试点配置。子文件夹中的配置文件在该文件夹内覆盖根目录的配置文件。
3. 运行时附加配置。

`manifest.json` 和 `config.json` 的格式详见 [manifest.json](#评测配置文件manifestjson) 和 [config.json](#测试点配置文件configjson)。

运行时附加配置详见命令行参数文档（TODO）。

运行时附加配置会覆盖任何通过配置文件指定的配置。

> *For Developers* 测试点配置文件覆盖是在评测时进行的，详见 `lib.jury.jury_test`。

### 判题文件

判题文件包括：

- **校验器（checker）** 文件名包含 `checker` 或 `chk` 的文件。
- **交互库（interactor）** 文件名包含 `interactor` 的文件。
- **函数式交互题交互单元（grader）** 文件名包含 `grader` 的文件。
- **头文件（headers）** 扩展名为 `.h` 或 `.hpp` 的文件。

推荐将这些文件放在根目录下，但放在数据文件夹其它位置也能被识别。

为了方便使用，本程序也会收集程序工作目录下的判题文件。

当存在多个同类别文件时，会按照修改时间选择最新的一个。

上述文件应当使用 C++ 编写，其它语言支持将在后续版本加入。

关于这些文件的规范，详见 [题型和判题文件](./题型和判题文件.md)。

## 评测配置文件（manifest.json）

- `name: str` 如果指定文件名，默认为 `None`。
- `checker: str` 校验器路径，默认为 `None`。
- `checker_conf` 校验器配置，包含如下字段的字典：
    - `limit: Limit` 校验器资源限制。
    - `safe: bool` 是否信任校验器。如果工作区未受信任，这一项被忽略，并锁定为 `False`。
    - `lang: LangTag` 编译校验器使用的语言标记，默认为 `c++14:O2`。
- `interactor: str` 交互库路径，默认为 `None`。
- `interactor_conf` 交互库配置，包含如下字段的字典：
    - `safe: bool` 是否信任交互库。如果工作区未受信任，这一项被忽略，并锁定为 `False`。
    - `lang: LangTag` 编译交互库使用的语言标记，默认为 `c++14:O2`。
- `graders: list[str]` 函数式交互题交互单元列表，这将覆盖自动收集的列表。
- `headers: list[str]` 编译时使用的头文件列表，这将覆盖自动收集的列表。
- `additional: list[str]` 编译时使用的附加文件列表，默认为空列表。
- `retry: int` 选手程序轻微超时时，重测的次数，默认为 `1`。
    > *For Developers* 详见 `lib.jury.jury`。

一些配置项如果未被指定，例如 `checker` `interactor` `graders` 和 `headers`，将被自动收集。

> *For Developers*
>
> `manifest.json` 支持的配置项是 `JudgeConf` 的子集，详见 `lib.ds.JudgeConf` 和 `lib.ds.read_judge_conf`。注意读取函数没有判断是否读取到了不应该被设置的项，例如 `checker_backup`，正确的配置文件也不应该包含这些项。
>
> 自动收集部分详见 `lib.collect.collect_problem`。

## 测试点配置文件（config.json）

- `limit: Limit` 测试点/子任务资源限制。
- `keep: bool` 当子任务不可能继续得分时，是否仍完成整个子任务的测试，默认未 `False`。

书写测试点配置文件时，为保持简便，你可以将资源限制的字段直接写在 `config.json` 下，例如：

```json
{
    "time": "1s"
}
```

和

```json
{
    "limit": {
        "time": "1s"
    }
}
```

是等价的。

> *For Developers* 此功能通过别名实现，详见 `lib.jury.TestConf` 和 `lib.jury.ModelAliasWrapper`。
