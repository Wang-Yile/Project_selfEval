# 配置文件

## 数据类型术语

本章介绍数据类型相关术语。

### 时间字面量

忽略空格，由数值、单位两部分组成。如果省略单位，默认为微秒。

单位可以为 `us` `usec` `ms` `msec` `s` `sec` `m` `min` 等。

例：`1500000` 等价于 `1500ms` 等价于 `1500 ms` 等价于 `1.5 sec`。

### 空间字面量

忽略空格，由数值、单位两部分组成。如果省略单位，默认为字节。

单位可以为 `B` `Byte` `K` `KiB` `M` `MiB` `G` `GiB` `T` `TiB` 等。

例：`536870912` 等价于 `524288K` 等价于 `512 MiB` 等价于 `0.5G`。

## 文件夹结构

本章介绍数据文件夹结构。

本程序不支持符号链接，不建议在数据文件夹中放置符号链接。

> *For Developers* 本程序将迁移到 `pathlib`，替代 `os.path`，期望获得更好的符号链接支持。

### 输入、输出文件和子任务

**输入、输出文件标识** 用于识别输入、输出文件的文件名子串。有别于常见的以文件扩展名（`.in` `.out`）区分输入、输出文件，文件名按照 `.` 字符分割后得到的每个子串都可以作为输入、输出文件标识。包含 `in` 的是输入文件，包含 `ans` 或 `out` 的是输出文件。

> *For Developers* `lib.collect` 提供了强制使用文件扩展名作为输入输出扩展名的方法，详见内部函数 `lib.collect._find_ansfile_strict` `lib.collect_find_ansfile_free`。

**测试点** 由一对输入、输出文件组合而成的测试数据。

**子任务** 一个或多个测试点组成的集合。一般而言，通过子任务中所有测试点才判定为通过该子任务。

数据文件夹下的每个子文件夹和测试点都是一个单独的子任务。子文件夹内部的子文件夹会被递归地加入该子文件夹指代的子任务。

示例：

```
data
├── 1.ans
├── 1.in
├── 2.in
├── 2.out
└── sub
    ├── 3.ans
    ├── 3.in
    └── sub-sub
        ├── 4.ans
        └── 4.in
```

上述文件结构将识别出四个测试点，三个子任务：

1. `1.in, 1.ans`
2. `2.in, 2.out`
3. `sub/3.in, sub/3.ans` `sub/sub-sub/4.in, sub/sub-sub/4.ans`

### 配置文件

本系统使用两种配置文件：

1. **manifest.json**：放在数据文件夹根目录，描述整个题目的元数据，包含题目标题、时间限制、内存限制等全局配置。
2. **config.json**：可以放在数据文件夹根目录或子文件夹中，描述特定测试点或子任务的评测配置。

### 判题文件

判题文件包括：
- **校验器 (checker)**：文件名需包含 `checker` 或 `chk`
- **交互库 (interactor)**：文件名需包含 `interactor`
- **函数式交互题辅助代码 (grader)**：文件名需包含 `grader`
- **头文件 (headers)**：扩展名为 `.h` 或 `.hpp`

这些文件可以放在数据文件夹的任何位置，系统会自动收集。当存在多个同名文件时，会按照修改时间选择最新的一个。

## manifest.json

`manifest.json` 是题目的主配置文件，必须放在数据文件夹的根目录。它包含以下字段：

*name*：字符串，题目标题（可选）。
*time*：时间字面量，全局时间限制（可选，默认1秒）。
*time_redundancy*：时间字面量，全局时间冗余量（可选，默认200ms）。
*memory*：空间字面量，全局内存限制（可选，默认512MiB）。
*memory_redundancy*：空间字面量，全局内存冗余量（可选，默认4MiB）。
*stack*：空间字面量，全局栈空间限制（可选，默认-1表示不限制）。
*fsize*：空间字面量，全局输出文件大小限制（可选，默认64MiB）。
*checker*：字符串或对象，校验器路径或程序配置（可选）。
*checker_backup*：字符串，备用校验器路径（可选）。
*checker_conf*：对象，校验器配置（可选）。
*checker_conf.time*：时间字面量，校验器运行时间限制（可选，默认同题目限制）。
*checker_conf.time_redundancy*：时间字面量，校验器时间冗余量（可选）。
*checker_conf.memory*：空间字面量，校验器运行内存限制（可选，默认同题目限制）。
*checker_conf.memory_redundancy*：空间字面量，校验器内存冗余量（可选）。
*checker_conf.stack*：空间字面量，校验器栈空间限制（可选）。
*checker_conf.fsize*：空间字面量，校验器输出文件大小限制（可选）。
*checker_conf.safe*：布尔值，是否在安全模式下运行校验器（可选，默认false）。
*checker_conf.lang*：字符串，校验器使用的语言和编译选项（可选，默认"c++14:O2"）。
*interactor*：字符串或对象，交互器路径或程序配置（可选）。
*interactor_backup*：字符串，备用交互器路径（可选）。
*interactor_conf*：对象，交互器配置（可选）。
*interactor_conf.safe*：布尔值，是否在安全模式下运行交互器（可选，默认false）。
*interactor_conf.lang*：字符串，交互器使用的语言和编译选项（可选，默认"c++14:O2"）。
*graders*：字符串数组，函数式交互题的grader文件列表（可选）。
*headers*：字符串数组，头文件列表（可选）。
*additional*：字符串数组，附加文件列表（可选）。
*retry*：整数，重试次数（可选，默认0）。

## config.json

`config.json` 可以放在数据文件夹的任何子目录中，用于覆盖该目录下测试点的配置。它支持以下字段：

*time*：时间字面量，时间限制（可选，覆盖全局配置）。
*time_redundancy*：时间字面量，时间冗余量（可选，覆盖全局配置）。
*memory*：空间字面量，内存限制（可选，覆盖全局配置）。
*memory_redundancy*：空间字面量，内存冗余量（可选，覆盖全局配置）。
*stack*：空间字面量，栈空间限制（可选，覆盖全局配置）。
*fsize*：空间字面量，输出文件大小限制（可选，覆盖全局配置）。
*keep*：布尔值，是否保留该测试点的临时文件（可选，默认false）。

### 配置继承规则

1. 数据文件夹根目录的 `manifest.json` 提供全局默认配置
2. 子文件夹中的 `config.json` 可以覆盖父文件夹的配置
3. 最内层文件夹的配置优先级最高
4. 未设置的配置项会继承父文件夹的配置

### 配置示例

假设有以下文件夹结构：

```
data/
├── manifest.json
├── easy/
│   ├── 1.in
│   ├── 1.ans
│   └── config.json
└── hard/
    ├── 2.in
    ├── 2.ans
    └── config.json
```

`manifest.json`:
```json
{
  "time": "1s",
  "memory": "512MiB"
}
```

`easy/config.json`:
```json
{
  "time": "2s"
}
```

`hard/config.json`:
```json
{
  "time": "5s",
  "memory": "1GiB"
}
```

最终配置结果：
- `easy/1` 测试点：`time=2s`, `memory=512MiB`（时间覆盖，内存继承）
- `hard/2` 测试点：`time=5s`, `memory=1GiB`（时间和内存都覆盖）
