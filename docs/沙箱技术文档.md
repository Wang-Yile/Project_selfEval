# 沙箱技术文档

使用 sandbox-tiny 运行的程序使用系统调用和文件操作没有额外限制。

## 系统调用

沙箱通过 seccomp-bpf 捕获系统调用，采用白名单放行。

seccomp-bpf 维护一个快速白名单，在该名单内的系统调用是安全的，会被快速放行。其包含 read、write 等常用安全系统调用和 tgkill、sendmsg 等沙箱启动需要的通常安全的系统调用。

如果系统调用不在快速白名单中，例如 openat，将通过 seccomp 用户空间提醒交给沙箱主程序处理，主程序维护另一个白名单，并可能执行一些更复杂的检查。

查看 sandbox.cpp `install_filter_raw` 函数和 `handle_syscall` 函数了解详细信息。

部分涉及文件的系统调用会检查是否有对应权限，详见 [文件许可机制](#文件许可机制)。

## 文件许可机制

有四种文件许可：只读、只写、读写、软拦截，前三种权限本质是 ACC Mode。

文件权限申请有四种：存在权限、读、写、读写。

| 文件权限申请 | 说明 | 备注 |
| :-: | :-: | :-: |
| 存在权限 | 拥有读、写权限中的任意一种 | 没有文件操作时应该使用此权限，例如处理 dup 系统调用 |
| 读 | 拥有只读/读写权限 | |
| 写 | 拥有只写/读写权限 | |
| 读写 | 拥有读写权限 | 不常用 |

权限按 `(path, mode)` 的方式给出，必须保证 path 的父目录存在。

权限检查跟随符号链接。授权和检查时，通过 `fs::canonical` 解析父目录（若不存在父目录则判定为非法系统调用）的所有符号链接，从根目录开始逐级解析。特别地，对根目录下项目的操作直接判定为非法系统调用；直接放行对 `/proc/self/`，`/proc/thread-self` 的读取，对 `/dev/fd/` 的读取和写入。权限检查失败将判定为非法系统调用，并可能附带一些检查时的信息。

特别地，如果申请的项目不存在，判定为非法系统调用；如果申请的项目本身或其任何一级父目录存在软拦截，文件操作将失败，错误码为 EPERM，但不判定为非法系统调用。

默认放行对以下项目的读取：

```
/etc/ld.so.cache
/lib/
/usr/lib/
/dev/random
/dev/urandom
/dev/stdin
/etc/localtime
标准输入流连接到的终端
```

默认放行对以下项目的读取和写入：

```
/dev/null
/dev/stdout
/dev/stderr
标准输入/输出/错误流
```

默认软拦截如下项目：

```
/etc/ld.so.preload
```

## 计时和超时杀死

程序用时为用户态时间和系统态时间之和，精度为微秒。

评测子进程和主进程都有超时杀死机制：

- 子进程采用程序用时判定超时杀死。
- 主进程采用向子进程发送恢复信号后，子进程运行的实际时间判定超时杀死。
